# Bayesian Model Discovery

**Find the functional form of an unknown system: a language model proposes candidate models, a Bayesian
engine fits and weighs them, and expected information gain picks the next experiment.**

[![License: MIT](https://img.shields.io/badge/license-MIT-blue.svg)](LICENSE)
[![Python 3.12](https://img.shields.io/badge/python-3.12-blue.svg)](REQUIREMENTS.md)

A language model proposes model families (functional forms with an observation distribution) from a
*belief packet*: the observations so far, the current expressions, their evidence, parameter summaries
and prediction errors. Rather than predicting directly in context, the engine fits every candidate to
all observations by sequential Monte Carlo (SMC, in PyMC), keeps the best-supported families in a pool of
at most twelve, and predicts with their evidence-weighted average (Bayesian model averaging, BMA). The
next experiment maximizes the joint expected information gain (EIG) about which family generated the
data and about its parameters, and each new observation updates the fits and feeds the next proposals.

![One round of the loop: the language model proposes candidates from the belief packet; the engine validates, fits by SMC, admits the top twelve by evidence, predicts by Bayesian model averaging and chooses the next design by joint EIG; the outcome is added to the data and the pool is refit](docs/media/loop.svg)

[`FLOW.md`](FLOW.md) walks through each step and names the module that implements it.

> Research code. Interfaces and file formats can change without a deprecation period.

## Install

Linux on x86-64, Python 3.12, git and a C/C++ compiler such as `g++` (PyTensor compiles C code the first
time it builds a model). From the repository root:

```bash
python3.12 -m venv .venv
```

```bash
source .venv/bin/activate
```

```bash
pip install -c requirements.lock -e ".[dev]"
```

Or, on a clean Linux host, let the provisioning script build the same environment from the lock file
(it installs Python 3.12 with `uv` if needed, checks the pinned versions, makes no LLM calls and never
reads a `.env` file):

```bash
bash scripts/provision.sh
```

With `--with boxinggym,neuronbench,forcebench` it also fetches the external benchmark code at its pinned
commits, builds the separate ForceBench environment and writes `.bmd_env.sh` with the variables the run
scripts read; `--smoke` ends with a one-round mock run. [`REQUIREMENTS.md`](REQUIREMENTS.md) lists
everything the code needs.

## Run it (no API key, no cost)

Three rounds of the full loop on the synthetic count benchmark, with the built-in mock proposer in place
of the LLM:

```bash
python -m bayes_model_discovery.experimental.core_count --profile dev --proposer mock --seed 11 --cell 111 --rounds 3 --output runs/quickstart_synthcount
```

It takes a few minutes, mostly PyTensor compilation and SMC, and prints a `FIT` line (log evidence) for
each fit and a `SCORE` line (held-out NLL) for each scoring step. One cell of any benchmark, through its
own runner and with the mock proposer by default:

```bash
python scripts/bmd_run.py synthcount --arm joint_eig --rounds 2 --profile dev --output runs/smoke
```

The output folder must not exist yet; no runner overwrites one. [`FLOW.md`](FLOW.md#the-run-folder)
describes the run folder, and [`USAGE.md`](USAGE.md) the arms per benchmark, the dry run, the paid-run
safeguards and the tests.

## How the experiments were run

The benchmark runs used the engine in this tree under one shared protocol: an initial batch of twelve
proposals, a pool of at most twelve models, one LLM call with three candidates per round and an archive
review every fifth round (NeuronBench starts from four fixed mechanisms, keeps six and has no review).
Runs lasted 30 rounds (ForceBench 16, NeuronBench 5) with seeds 31, 37 and 41 (one BoxingGym task used 47
in place of 37) and compared the five design criteria (four on ChemBench), next to a direct in-context
learning forecaster that received the same observations. The run records and the exact launch trees are
not in this repository, but every run records the sha256 of the engine source files it loaded and of the
prompt file it sent; [`USAGE.md`](USAGE.md#reproducing-the-benchmark-runs) explains how to tie a run to
this code.
